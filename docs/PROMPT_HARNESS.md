# 프롬프트 엔지니어링 실험 하네스

> ViralCraft AI — "여러 번 실험"을 정량 근거로 남기기 위한 실험 설계서
> 목적: 프롬프트/입력 방식을 바꿔가며 출력 품질을 **재현 가능하게 측정**하고, 최적 조합을 결론낸다.

---

## 0. 왜 필요한가

현재 `geminiService.ts`의 프롬프트는 한 번에 손으로 작성된 단일 버전이다.
- 어떤 프롬프트가 더 좋은지 비교한 적이 없다 → 보고서에 쓸 근거가 없다.
- F5(키프레임 입력) 효과를 주장하려면 **같은 잣대로 측정**해야 한다.

하네스 = (프롬프트 변형 × 입력 방식 × 평가지표)를 자동으로 돌리고 표로 남기는 틀.

---

## 1. 실험 변수

### 1-A. 프롬프트 변형 (Prompt Variants)
- **V0 베이스라인:** 현재 `ANALYSIS_SCHEMA` 프롬프트 그대로.
- **V1 역할·제약 강화:** "World-Class Viral Architect" + 출력 길이·금지어 제약.
- **V2 Few-shot:** 모범 분석 예시 1~2개를 프롬프트에 포함.
- **V3 CoT 분리:** 1) 관찰 → 2) 구조화 추론 → 3) JSON 출력 단계 분리.
- **V4 CV 메타 주입:** F2/F3 산출(컷 타임스탬프, 모션 지표)을 프롬프트에 함께 제공.

### 1-B. 입력 방식 (Input Modality)
- **I0:** 영상 전체 업로드 (현행)
- **I1:** 키프레임 8장 + 메타
- **I2:** 키프레임 4장 + 메타
- **I3:** 링크 텍스트만 (현행 링크 분석 — 환각 대조군)

### 1-C. 모델/디코딩 설정
- 모델: 고정(예: `gemini-2.5-flash`) — 변수 통제.
- temperature: {0.2, 0.7} 2수준만(비용 절약).

---

## 2. 평가 지표 (Metrics)

| 지표 | 측정 방법 | 자동/수동 |
|------|-----------|-----------|
| **스키마 충족률** | `responseSchema` 필수필드 채움 비율, JSON 파싱 성공률 | 자동 |
| **타임스탬프 정합성** | 모델이 낸 keyTimestamps vs F2(CV) 컷의 시간 오차(초) | 자동 |
| **일관성(self-consistency)** | 동일 입력 3회 실행 결과의 분산/중복도 | 자동 |
| **지연(latency)** | 요청→응답 ms | 자동 |
| **토큰/비용** | usage 메타 또는 추정 | 자동 |
| **유용성(human rubric)** | 아래 5점 루브릭으로 팀원 2명 평가 평균 | 수동 |

### Human Rubric (각 1~5점)
1. 훅 분석이 영상 실제 내용과 일치하는가
2. 리메이크 전략이 구체적·실행가능한가
3. 한국어 자연스러움/슬랭 적절성
4. 환각(없는 장면 지어냄) 없음
5. 스토리보드 시각 컨셉의 명확성

## 4. 실행 구조 (간단 러너)

```
experiments/
  prompts/        # V0.txt ... V4.txt (프롬프트 본문 분리)
  inputs/         # 샘플영상, 키프레임 세트(I1/I2), 링크(I3)
  run_harness.ts  # 매트릭스 순회 → Gemini 호출 → 결과 JSON 저장
  results/        # E01.json ... (출력+지연+토큰 raw)
  evaluate.ts     # 자동지표 계산 → results.csv
  rubric.csv      # 사람 평가 입력
  report.ipynb    # CSV → 그래프(막대/박스플롯)
```

핵심 원칙
- **프롬프트는 코드에서 분리**(파일로) → diff·버전관리·재현.
- 각 실행 결과(입력·출력·설정·시각)를 통째로 저장 → 사후 재집계 가능.
- 시드/온도 고정으로 통제, 일관성은 의도적 3회 반복으로 측정.

---

## 5. 가드레일 (품질 안정화)

- **JSON 강제:** `responseMimeType: application/json` + `responseSchema`(이미 적용). 파싱 실패 시 1회 재요청.
- **환각 억제:** "영상/키프레임에서 관찰되지 않은 내용은 추정하지 말고 'unknown'으로" 지시(V1+).
- **CV 그라운딩:** V4에서 컷 타임스탬프를 사실로 제공 → 모델이 시간을 지어내지 않게.
- **길이·언어 제약:** 내레이션 글자수 상한, 한국어 고정.

## 6. 보고서에 남길 결론 (예시 골격)

- "입력방식: I1(키프레임)이 I0(전체영상) 대비 지연 −X%, 토큰 −Y%, 루브릭 동등(Δ<0.3)."
- "프롬프트: V4(CV 메타 주입)가 타임스탬프 오차를 N초→M초로 줄이고 환각 점수 개선."
- "최종 채택: V4 × I1 × temp 0.2."

이 결론이 곧 본 프로젝트의 **프롬프트 엔지니어링 기여**이자 발표 핵심 슬라이드다.
