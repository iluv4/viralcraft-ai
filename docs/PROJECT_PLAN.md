## 0. 한 줄 요약 (재정의)

기존 ViralCraft는 **영상 링크/파일을 Gemini API에 그대로 던지는** 구조다.
- 링크 분석은 모델이 영상을 실제로 보지 못해 **사실상 환각**이고,
- "핵심 장면(keyTimestamps)"·"템포"는 **모델이 지어낸 텍스트**이며,
- 매번 **영상 전체**를 업로드해 **느리고 비싸다**.

> **본 프로젝트의 차별점:** 영상에서 **컴퓨터비전으로 진짜 정보를 추출**한다.
> 샷 경계 검출(Shot Boundary Detection)로 장면 전환 지점을 찾고, 옵티컬 플로우로 템포를 **수치화**하며, 품질 지표로 대표 키프레임을 자동 선정한다. **이렇게 뽑은 소수의 키프레임만 Gemini에 전달**해 속도·비용을 줄이고, 분석 근거를 객관화한다.

이 재정의로 (1) CV 알고리즘 콘텐츠 확보 (2) 처리 속도 최적화 (3) 프롬프트 엔지니어링 실험의 정량 근거를 동시에 얻는다.

## 1. 현재 코드 분석 (As-Is)

**스택(실제):** React 19 + Vite 6 + TypeScript + Tailwind4/shadcn + Firebase(Auth/Firestore) + `@google/genai`. 백엔드 없음, 전부 클라이언트 사이드.

**흐름:** `LandingPage → Dashboard(분석/생성) → ProjectAnalysis(전략·스토리보드·TTS·채팅)`

**잘 된 점**
- Firestore 보안 규칙 수준급(Dirty Dozen 방어, 불변필드·서버타임 강제).
- 이미지(Base64) 1MB 초과 회피용 `scenes`/`frames` 서브컬렉션 분리 아키텍처.

## 2. To-Be 아키텍처

```
┌─────────────┐     영상 파일      ┌──────────────────────────────┐
│  React (FE) │ ─────────────────▶ │  CV 모듈                      │
│  대시보드    │                    │  ① 프레임 추출 (ffmpeg.wasm)   │
│  결과 시각화 │ ◀───키프레임/지표── │  ② 샷 경계 검출(히스토그램 χ²) │
└─────────────┘                    │  ③ 옵티컬 플로우 템포 수치화    │
       │                           │  ④ 키프레임 품질 선정          │
       │ 키프레임 N장 + 메타        └──────────────┬───────────────┘
       ▼                                          ▼
┌──────────────────────────┐          ┌────────────────────────┐
│ 백엔드 프록시 (FastAPI)    │ ───────▶ │ Gemini API (키 서버보관) │
│ - API 키 은닉(#1 해결)     │ ◀─────── │ 분석/전략/TTS/이미지     │
│ - (선택)무거운 CV 서버처리 │          └────────────────────────┘
└──────────────────────────┘
       │
       ▼  Firestore (텍스트 기획안 + scenes/frames 서브컬렉션)
```

**CV 실행 위치 선택 (W1 초반 확정)**
- **권장 A — 클라이언트 CV(ffmpeg.wasm + OpenCV.js):** 인프라 0, 데모 쉬움. 무거운 영상은 다운샘플링으로 대응.
- **대안 B — Python FastAPI + OpenCV 백엔드:** CV 수업 표준 스택, 무거운 처리 유리, **API 키 은닉(#1)까지 동시 해결**. 배포 1대 필요.

> 추천: **B(백엔드 OpenCV)**. CV 코드가 Python/OpenCV로 깔끔하고, 보안 이슈 #1을 구조적으로 해결하며, 발표 시 "프론트=시각화 / 백엔드=CV 파이프라인"으로 역할이 선명해진다. 인프라가 부담되면 A로 폴백.

상세 알고리즘은 [`CV_PIPELINE.md`](./CV_PIPELINE.md), 프롬프트 실험은 [`PROMPT_HARNESS.md`](./PROMPT_HARNESS.md) 참고.

## 3. 추가 개발 백로그 (우선순위)

### P0 — CV 핵심 (수업 평가의 본체)
- [ ] **F1 프레임 추출 파이프라인**: 영상 → 균일/적응 샘플링 프레임 추출
- [ ] **F2 샷 경계 검출(SBD)**: 인접 프레임 HSV 히스토그램 χ² 거리 + 임계값 → 컷 지점 → **진짜 `keyTimestamps`** 생성 (이슈 #3 대체)
- [ ] **F3 모션/템포 정량화**: 프레임 차분 또는 Lucas-Kanade 옵티컬 플로우 → 평균 모션 크기·컷 빈도 → "템포"를 **수치+그래프**로 (현재 환각 텍스트 대체)
- [ ] **F4 대표 키프레임 선정**: Laplacian variance(선명도)·colorfulness·(선택)saliency 점수화 → 샷별 베스트 프레임 → 가짜 썸네일 생성 대체
- [ ] **F5 속도 최적화**: 전체영상 대신 **키프레임 N장만** Gemini 전송 → 지연/토큰 **before-after 측정 그래프**

### P1 — 안정화·보안
- [ ] **B1 백엔드 프록시**로 API 키 은닉 (이슈 #1)
- [ ] **B2 Firestore 규칙에 `brandImage`/`userPhoto` 허용** (이슈 #2)
- [ ] **B3 실존 모델명 고정** (이슈 #4): `gemini-2.5-flash`(텍스트)·`gemini-2.5-flash-image`(이미지) 등으로 통일 + 폴백
- [ ] **B4 ENV 예시·셋업 문서** (이슈 #8)

### P2 — 기능 확장 (목표: 기능 확장까지)
- [ ] **E1 프롬프트 엔지니어링 실험 하네스** (변형 프롬프트 × 입력방식 정량 비교 — 보고서 핵심 자료)
- [ ] **E2 멀티턴 채팅** 정상화 (이슈 #5)
- [ ] **E3 TTS 재생/정지 상태 정상화** (이슈 #6)
- [ ] **E4 결과 공유/링크, 프로젝트 페이지네이션** (이슈 #7)
